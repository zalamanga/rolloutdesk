# RolloutDesk design read

The user's retained direction is a light, orderly work application with actual screenshots and explanatory documentation. The new application's design interprets that direction for release configuration; it is not an additional user quotation.

Reading this as: a release-control workspace for a developer comparing a draft with the active configuration, in a light editorial work-app style, ENERGY 1 / RHYTHM 2 / MOTION 1.

- Use white working surfaces, warm pale-grey surroundings, dark ink and one restrained teal action accent. Amber/red represent warnings and conflicts with explicit text.
- The identity motif is the draft-to-published comparison: a labelled draft, an immutable active revision and a chronological publication history. These are stored application concepts, not decorative cards.
- The registry is a compact table of three actual demo flags with separate staging and production evidence. The detail page gives the comparison priority and keeps publication/rollback actions near their version context.
- Use system sans-serif for reading; monospace is limited to flag keys, JSON, IDs and hash protocol facts. No external font service, graphic logo, avatar or decorative illustration is needed.
- Navigation follows the work: Flags, Playground and Audit. Keep environment selectors visible and label any draft-only result so it cannot be mistaken for production behavior.
- Work sheets have modest corners and borders; buttons have clear boundaries and 44 px minimum targets. Teal marks the main operation rather than every panel.
- Stack comparisons on narrow screens, preserve form state across refresh, and use local scroll regions for wide evidence tables. Motion is only hover, focus and pressed feedback.
- Real counts and history come from PostgreSQL. Do not invent exposure statistics, rollout success rates or customer impact. Preview and client-evaluation subject inputs are synthetic and are not stored or logged; allowlist IDs remain part of stored draft and publication configurations.
